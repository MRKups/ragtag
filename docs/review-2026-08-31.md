## Findings

### Critical — External streaming corrupts split UTF-8 tokens

`execute_query` decodes every arbitrary `reqwest::Response::bytes_stream()` chunk independently with `String::from_utf8_lossy` before assembling Server-Sent Events (`src-tauri/src/lib.rs:553-600`). TCP/HTTP chunk boundaries are byte-oriented, so a multibyte character may span two chunks. Each partial sequence is replaced with U+FFFD permanently before the buffer is combined. Any external provider that emits non-ASCII content under that boundary produces corrupted answer text. Buffer raw bytes until an entire SSE event is available, then UTF-8-decode that event, or use an incremental UTF-8 decoder.

### High — A failed deletion can create an indexed document without vectors

`delete_document` deletes a document's LanceDB rows before deleting its SQLite registry record (`src-tauri/src/lib.rs:714-716`) without a recovery marker or compensation. If the SQLite operation fails after the vector mutation, the registry row remains `indexed` but retrieval and citations have no vectors. This violates the registry/vector consistency contract in `docs/app-architecture.md:35-38` and is not recovered at startup because indexed rows are not normally requeued. Stage deletion durably, or make the record non-indexable before the vector deletion and recover incomplete deletions on startup.

### High — Fast external-to-local switching can leave local inference permanently unavailable

The initialization task reads `inference_mode` asynchronously (`src-tauri/src/lib.rs:197-203`) and, for external mode, only clears `LLM_INIT_IN_PROGRESS` immediately before returning (`:203-207`). If a user switches external → local after that read but before the flag is cleared, `set_setting` calls `begin_first_run_init`, observes the flag set, and starts no local initializer (`:797-804`, `:191-312`). The old task then exits; no later trigger starts the selected local model, so queries remain unavailable until restart. Serialize mode changes and initialization state, or re-read the desired mode after clearing the flag and schedule the current desired initialization.

### Medium — A transient registry read abandons queued ingestion until restart

The only worker dequeues a document ID and does not retry it when `repo.get_by_id` fails; it logs and discards the item (`src-tauri/src/lib.rs:1037-1039,1083-1090`). The document row remains `queued`, but recovery enumerates queued records only after embedder initialization at startup (`:127-166`), not during the running session. A transient SQLite failure therefore leaves a successful upload visibly queued forever until the application is restarted. Requeue the ID with bounded backoff, or mark the document failed with a retry path.

### High — Local-model failure can block ingestion indefinitely

When local-model download/build failure arrives before the embedding model is ready, the frontend sets the global phase to `error` (`frontend/src/lib/stores/app-state.svelte.ts:55-62`). A subsequent `embedder_ready` correctly sets `embedderAvailable`, but `#tryBecomeReady` refuses to leave that error phase (`:39-43,139-143`). `AppInitializer` consequently continues to block the whole application, including document upload and Settings, even though the backend has made ingestion available. This contradicts the staged-availability contract in `docs/app-architecture.md:72-73,92-96` and the known recovery requirement in `docs/tracker.md:14-15`. Separate model-query failure from application/embedding readiness so the UI enters its usable state when the embedder succeeds.

### Medium — Rejected files are resubmitted and cannot be removed

The upload component labels unsupported and oversized files as `error` (`frontend/src/lib/components/DocumentUpload.svelte:48-66`), then treats both `pending` and `error` as upload candidates (`:73-81,187-199`). Clicking Upload therefore transmits files the UI has already rejected, and the backend rejection returns them to `error`. The error branch renders only an alert icon, not the remove button (`:166-181`), so the user cannot clear the invalid entry or regain a clean upload list without leaving the page. Restrict submission to `pending`; render removal (and optionally retry) as separate error actions.

### Medium — Valid PDFs smaller than 1 KiB are rejected

The PDF signature validator requires `bytes.get(..1024)` to succeed before it scans for `%PDF-` (`src-tauri/src/lib.rs:40`). For every file shorter than 1,024 bytes this returns `None`, regardless of a valid signature at byte zero. Minimal but valid PDFs are therefore rejected as “not a PDF.” Inspect `bytes[..bytes.len().min(1024)]` instead.

### Medium — Unicode document filenames cannot cross the IPC boundary

The frontend passes the raw `File.name` as the `X-Filename` request header (`frontend/src/lib/api.ts:7-16`), while the backend accepts it only when the header can be converted to a Rust HTTP text value (`src-tauri/src/lib.rs:322-327`). HTTP header text rejects non-ASCII UTF-8; ordinary valid filenames such as `操作说明.pdf` fail after selection even though the UI accepts their `.pdf` extension. Encode the filename explicitly or carry it in a structured command argument while retaining the binary request body.

### Medium — Production builds can package stale frontend output

`build-frontend` declares only `.svelte` and `.ts` files as Taskfile sources (`Taskfile.yml:101-110`). Once `frontend/dist/index.html` exists, go-task does not rerun Vite for changes to `frontend/index.html`, `vite.config.ts`, static assets, package configuration, or lockfile. `build` and `bundle` depend on that task (`:83-97`), so a release can package stale frontend assets while reporting success. Track all Vite inputs or remove the task-level incremental source optimization.

### Medium — Hybrid-search citations receive false confidence labels

LanceDB reciprocal-rank-fusion results carry fused relevance in `_relevance_score`, but the result parser reads only `_distance` and substitutes `0.0` when it is absent (`src-tauri/crates/persistence/src/lancedb.rs:226-235`). The command then converts this to `1.0 / (1.0 + score)` (`src-tauri/src/lib.rs:491-498`); consequently FTS/hybrid results with no `_distance` become 1.0 and the UI displays the “High” confidence tier (`frontend/src/lib/components/ConfidenceBadge.svelte:4-5`). This presents an invented retrieval-confidence signal alongside source citations. Read and propagate the fused relevance score, with a documented normalization for UI presentation.

### Medium — “Reset all data” reports success after partial cleanup

The restart-side reset handler deliberately discards every deletion result for documents, vectors, database files, and models, then clears the reset sentinel unconditionally (`src-tauri/src/lib.rs:970-990`). A locked file, permissions failure, or I/O error can leave user data behind while the operation has already reported restart/success and removed the only retry marker. Preserve the sentinel on failure and report the specific cleanup failure after restart, or make cleanup retries idempotent until it completes.

### Critical — Documents with fewer than 256 chunks cannot be indexed

After the first write, ingestion unconditionally builds LanceDB’s default IVF-PQ index and propagates an index-creation failure (`src-tauri/crates/persistence/src/lancedb.rs:103-120`). The pinned Lance 10.0.0 implementation behind LanceDB 0.37.1 uses 8-bit PQ and explicitly rejects training sets smaller than its 256 centroids. A normal short PDF yielding fewer than 256 chunks therefore fails after vectors are written but before SQLite is marked indexed; startup retries repeat the same deterministic failure. Skip IVF-PQ below its training minimum and use flat search until the table is sufficiently large.

## Overall assessment

The intended architecture is coherent: local-first boundaries are explicit, domain types are isolated from adapters, the repository documents its SQLite/LanceDB lifecycle, and the frontend type/Svelte check is clean. The implementation is not yet reliable enough for normal document use. The IVF-PQ threshold prevents the common short-document path from completing, while the readiness and queue/retry defects can leave otherwise recoverable workflows stuck. External-mode text corruption and misleading confidence labels also undermine answer quality.

The active tracker separately retains six legitimate follow-ups: B112 and B121 still lack a local-model failure retry/restart path; B132 still has only a global extraction marker; B133 still filters document lifecycle after bounded retrieval; B134 still treats external-route selection as ready without validation; and B137 still lacks persisted chunking provenance and reindexing on chunk-setting changes. They are not remediated by the work recorded below.

## Revalidation — completed

The following outcomes supersede the initial severity and wording where they differ. Every original finding remains a real defect; four were downgraded after tracing its exact activation and recovery behavior.

1. **External UTF-8 SSE decoding — confirmed; Medium, not Critical.** `bytes_stream()` exposes raw transport `Bytes`, not complete UTF-8/SSE records. Lossy decoding precedes event buffering, so a multibyte character split across records becomes U+FFFD permanently. It is conditional on external inference and a split non-ASCII character.
2. **Cross-store document deletion — confirmed; Medium, not High.** A SQLite failure or crash after Lance deletion can leave an indexed registry row without vectors. An ordinary SQLite failure is visible and retrying delete normally recovers it; crashes and abandoned failures have no automatic reconciliation.
3. **External-to-local initialization race — confirmed; High.** An old initializer can read `external`, a concurrent switch can observe its in-progress flag and schedule no local initializer, then the old task exits. The stale `llm_ready` can enable query UI without a local model. This persists until another local-init trigger, such as switching away and back, or restart.
4. **Lost queued work after registry error — confirmed; Medium.** A dequeued ID is discarded on `get_by_id` failure while the document remains queued. No running-session recovery re-enqueues it.
5. **Failure-order startup block — confirmed; High.** An LLM failure before `embedder_ready` sets the global phase to error; the later embedding-ready event cannot make the application usable. This blocks ingestion and Settings despite the documented staged-availability contract.
6. **Rejected upload retry trap — confirmed; Medium.** Invalid entries are submitted again, rejected again, and cannot be removed from the current list. Navigation clears the list and no persistent data is harmed.
7. **Sub-1 KiB PDF rejection — confirmed; Low, not Medium.** The exact range check rejects all shorter payloads before any PDF parser runs. This is an uncommon boundary failure with no persistence impact.
8. **Unicode filename upload — confirmed; Medium.** Desktop IPC creates an HTTP `Headers` object from the raw filename, which cannot carry a non-ByteString value; Rust header parsing/text conversion is also not a Unicode transport. Non-ASCII filenames must be encoded or moved out of the header.
9. **Stale frontend build artifact — confirmed; Medium.** A focused go-task reproduction verified that after `dist/index.html` exists, changing only an omitted Vite input such as `frontend/index.html` leaves `build-frontend` up-to-date and does not rerun Vite.
10. **Hybrid confidence labels — confirmed; Medium.** Hybrid LanceDB queries return RRF `_relevance_score`, but the adapter seeks `_distance`, substitutes zero when absent, and produces score 1.0/High. The RRF rank signal itself is not a calibrated confidence probability; the badge should be removed or deliberately mapped.
11. **Partial reset cleanup — confirmed; Medium, qualified.** The initial command only acknowledges a restart request. On the restart path, cleanup errors are discarded and the sentinel is cleared, so retained data gets neither an error nor an automatic retry.
12. **IVF-PQ threshold — confirmed; High, not Critical.** Default eight-bit PQ requires at least 256 vectors. The threshold is table-wide, so a short document succeeds after the shared table is large enough. On an empty installation, documents below that cumulative threshold fail after vector persistence and before indexing.

Two additional observations were deliberately excluded from the material findings:

- `DocumentList` can create polling/listeners after unmount if an initial IPC request finishes late. It is a detached-resource concern, but current source does not demonstrate a user-visible failure or data loss.
- `resetAllData` declares `{ requires_restart: boolean }` while the command returns `{ restarting: true }`. Its only caller ignores the field, so this is type-contract hygiene rather than a current behavior defect.

### Corrected health assessment (before remediation)

At revalidation, the project had **three high-priority reliability defects**: the first small-enough vector store could not index short documents, a model-download failure could block the entire usable UI, and an inference-mode race could leave query unavailable. The remaining confirmed defects were material operational and UX issues, but their bounded activation or recoverability did not justify the original critical/high ratings.

The remediation below addresses each of those confirmed findings. It does **not** close the active tracker’s B112, B121, B132, B133, B134, or B137 follow-ups; their current, independently assessed status is recorded after the historical remediation evidence.

## Remediation — completed reviewed findings

- Deferred IVF-PQ until the shared LanceDB table reaches 256 vectors while retaining FTS and flat-vector retrieval below that threshold.
- Added durable `deleting` lifecycle state, startup deletion reconciliation, and reset-marker retention on cleanup failure.
- Re-enqueue transient registry-read failures with capped asynchronous backoff.
- Decode complete external SSE byte events before UTF-8 conversion.
- Serialized LLM initialization by generation, preventing stale readiness and missed local-mode initialization.
- Decoupled embedder readiness from local-model failure so ingestion and Settings remain available.
- Percent-encode/decode upload filenames, accept available short-file signature prefixes, and keep rejected uploads removable rather than submit-ready.
- Suppressed RRF-derived confidence badges, exposed retrieval mode explicitly, and removed Taskfile's incomplete Vite freshness gate.

- `cargo test --workspace` passed on Intel macOS with the repository's documented external ONNX Runtime configuration: 12 tests across 9 suites passed.
- `cargo test -p persistence` passed: the 256-vector threshold regression test passes.
- `cargo test -p mrk-ragtag-app` passed: 6 tests across 3 suites passed.
- `npm run check` passed with 0 errors and 0 warnings; `npm run build` and `task build-frontend` both completed successfully.
- Changed Rust files pass `rustfmt --check`.
