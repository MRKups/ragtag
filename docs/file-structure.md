# File Structure

This document outlines the current layout of the application.

## Root Directory

- `package.json`: NPM workspace / scripts for driving both Svelte and Tauri builds.
- `Taskfile.yml`: Root development-task entry point. Defines normal Apple Silicon tasks plus `dev-intel` and `build-intel`, which validate and dynamically link the externally maintained Intel ONNX Runtime.
- `opencode.jsonc`: Agent tooling configuration.
- `docs/`: Architecture, specification documentation, and implementation tracker.
- `frontend/`: Plain Svelte 5 SPA (no SvelteKit) built with Vite.
- `src-tauri/`: The Tauri Rust application shell.

## `frontend/` (Plain Svelte 5 + Vite SPA)

The frontend is a plain Svelte 5 application compiled by Vite, running inside a Tauri WebView as a Single Page Application (SPA). Hash-based routing is used to avoid server-side routing complexities.

- `index.html`: Static HTML entry point with `#app` mount target.
- `package.json`: Plain Svelte deps — no `@sveltejs/kit` or adapter.
- `svelte.config.js`: Compiler options only (runes mode enforced, no `kit` config).
- `vite.config.ts`: Direct `svelte()` Vite plugin with manual `$lib` alias resolution.
- `tsconfig.json`: Standalone config (no `.svelte-kit/` extend), with `$lib/*` path mapping.
- `src/app.d.ts`: TypeScript declarations file (minimal — no SvelteKit `App` namespace).
- `src/main.ts`: Entry point — mounts `App.svelte` into `#app`.
- `src/App.svelte`: Root app shell with a compact, draggable macOS-overlay titlebar, header nav, `AppInitializer` boot gate, hash-based page routing via `{#key}` blocks, and CSS View Transitions.
- `src/pages/`:
  - `QueryPage.svelte`: Query interface with streaming chat (left) and PDF viewer panel (right).
  - `DocumentsPage.svelte`: Document management — upload (left) and list (right).
  - `SettingsPage.svelte`: Application configuration.
- `src/lib/`:
  - `index.ts`: Barrel re-export entry for the `$lib` path alias.
  - `api.ts`: Typed wrappers around Tauri `invoke` commands.
  - `types.ts`: TypeScript interfaces mirroring Rust models.
  - `pdf-init.ts`: pdf.js worker initialization.
  - `router.svelte.ts`: Hash-based micro-router using Svelte 5 `$state` runes. Routes: `query`, `documents`, `settings`.
  - `assets/`: Static assets bundled by Vite (e.g., `favicon.svg`).
  - `stores/`: Svelte 5 `$state` stores:
    - `app-state.svelte.ts` — exports `AppState` class and `appState` singleton.
    - `query.svelte.ts` — exports `QueryState` class and `queryState` singleton.
    - `settings.svelte.ts` — exports `SettingsState` class and `settingsState` singleton.
  - `components/`: Reusable UI components — `AppInitializer`, `CitationList`, `ConfidenceBadge`, `DocumentList`, `DocumentUpload`, `DocumentViewer`, `PdfPage`, `PdfViewer`, `QueryInput`, `QueryResult`, `SettingsTab`, `Toggle`.
- `static/`: Static frontend assets.

## `src-tauri/` (Tauri App Shell)

The Tauri adapter layer connecting the OS, the UI, and the Rust backend.

- `tauri.conf.json`: Core configuration, build instructions, asset-protocol scope, and the macOS overlay titlebar/traffic-light placement.
- `capabilities/`: JSON files defining exact capabilities mapped to specific window labels.
  - `default.json`: Grants the main window baseline permissions plus declarative titlebar dragging.
- `Cargo.toml`: Defines the Rust workspace, including the root Tauri v2 app and the library crates in `crates/`. The root composes the current Tauri, SQLx, Tokio, FastEmbed, ONNX Runtime, keyring, and inference-client dependencies.
- `.env`: `DATABASE_URL` pointing to the SQLite file used by `cargo sqlx prepare` for offline query cache generation.
- `.sqlx/`: Offline query cache generated by `cargo sqlx prepare`. Must be checked into version control so the CI and other developers can build without a live database.

### `src-tauri/src/`

The binary crate — entry point and thin command wrappers.

- `main.rs`: Barebones entry point calling `mrk_ragtag_app::run()`.
- `lib.rs`: Core setup logic. Initializes `SqlitePool` and `AppState` (db pool, job queue, embedder, vector db, local LLM) inside `tauri::async_runtime::block_on`. Uses an `AtomicBool` (`INIT_STARTED`) to guard against duplicate first-run initializations. Initializes the `fastembed` model (`EmbeddingGemma300M`) in `spawn_blocking` during startup, with cache dir at `$APPLOCALDATA/models`. Runs startup recovery (resets stale `embedding` → `queued`, re-queues `queued` docs) *after* the embedder successfully initializes. Spawns background LLM init task (reads `model_id`/`gguf_filename` from `app_settings` with hardcoded fallbacks, downloads model weights via `hf-hub` with progress events, builds `mistralrs::Model` using a pre-quantized GGUF, stores in `Arc<RwLock<Option<Arc<Model>>>>`). Spawns background worker task that consumes doc IDs from the MPSC channel, runs the full `rag_pipeline::process_document` (extract → chunk → embed → LanceDB write → SQLite status update), and emits `document_indexed` / `document_failed` Tauri events. Registers commands: `upload_document`, `execute_query`, `list_documents`, `delete_document`, `get_settings`, `set_setting`.
- `state.rs`: Defines `AppState`, the Tauri managed state holding the SQLite pool, document-work queue, late-initialized embedder, vector database, local MistralRS model, and shared HTTP client.
- `model_download.rs`: `hf-hub` 1.0 model-download logic with resume support and a 3-attempt retry loop. Emits byte-level `model_download_progress` lifecycle events through its synchronous `ProgressHandler`.

### `src-tauri/crates/` (Business Logic Workspace)

Pure Rust library crates for portable, fast-testing business logic.

#### `crates/domain/` — Shared Types & Errors

Contains zero-infrastructure data types: models, errors, and IPC events. No `sqlx` or `tokio` dependencies.

- `Cargo.toml`: Minimal deps — `serde`, `uuid`, `jiff`, `thiserror`.
- `src/lib.rs`: Re-exports all public types.
- `src/models.rs`: `Document` struct (fields: id, filename, file_type, file_size_bytes, file_hash, storage_path, status, chunk_count, embedding_model, embedding_attempts, timestamps, error tracking) and `DocumentStatus` enum (`Queued | Embedding | Indexed | Failed`).
- `src/error.rs`: `AppError` enum with variants `NotFound`, `Database`, `Io`, `VectorDb`, `QueueFull`, `Internal`. Includes manual `Serialize` impl for Tauri IPC (structured `{ kind, message }`). `From<std::io::Error>` impl for `?` convenience.
- `src/events.rs`: `TokenEvent` enum (`Token | Done | Error`) and `Citation` struct — both derive `Serialize` + `Deserialize` for Tauri event streaming channels.

#### `crates/persistence/` — Data Layer

Database and vector store operations. Depends on `domain`, `sqlx`, `lancedb`, `arrow-*`, `tokio`.

- `Cargo.toml`: Dependencies for SQLite (`sqlx 0.9`), LanceDB (`0.37.1`), and the matching Arrow `58.4` API family.
- `src/lib.rs`: Re-exports `DocumentRepository`, `VectorDb`, and `init_pool`. Contains a private `fn sql_err(e: sqlx::Error) -> AppError` helper to work around orphan rule restrictions on `From` impls.
- `src/sqlite.rs`:
  - `init_pool()`: Creates the app data directory, opens a SQLite connection with `SqliteConnectOptions`, runs migrations, returns a `SqlitePool` (max 5 connections).
  - `DocumentRepository`: CRUD operations — `insert`, `update_status`, `get_by_id`, `list_all`, `delete_by_id` (maps raw rows through `DocumentRow → into_domain()`), `get_queued_ids` (fetches all `queued` doc IDs for crash recovery), and `reset_embedding_to_queued` (recovery: flips `embedding` back to `queued` on crash restart). Date/time columns use `CAST(... as TEXT)` with sqlx type overrides since SQLite has no native datetime type.
  - `AppSettingsRepository`: Key-value settings store — `get(key)` and `set(key, value)` with upsert on conflict. Stores keys like `inference_mode`, `external_base_url`, `generation_model`, `chunk_size`, `chunk_overlap`, `use_query_enhancement`.
- `src/lancedb.rs`:
  - `VectorDb`: Holds a LanceDB `Connection` and an `AtomicBool` for FTS index guard.
  - `init()`: Connects to a LanceDB directory on disk.
  - `schema()`: Arrow schema with `FixedSizeList(Float32, 768)` vectors, plus `document_id`, `page`, `chunk_index`, `content` columns.
  - `get_or_create_table()`: Opens existing `chunks` table or creates a new empty one. FTS index is deferred to first write.
  - `upsert_chunks()`: Acquires a static `Semaphore(1)` write lock (prevents LanceDB commit conflicts), runs `merge_insert` on composite key `[document_id, page, chunk_index]` for idempotent upserts, then rebuilds the FTS index on the first call per session (`AtomicBool` swap).
  - `hybrid_search()`: Performs FTS + dense vector hybrid search via Reciprocal Rank Fusion. Falls back to vector-only if FTS index is missing or errors. Returns deduplicated `Vec<SearchResult>` capped at the requested limit.
  - `delete_chunks()`: Deletes all chunk rows for a given `document_id` using a string filter expression. Used by the `delete_document` command before SQLite row deletion.
- `migrations/`:
  - `20240101000000_initial.sql`: Creates `documents` table (id, file metadata, processing status, embedding metadata, timestamps, error tracking) with indexes on `status`, `file_hash` (unique), and `created_at`. Creates `app_settings` key-value table.

#### `crates/rag_pipeline/` — Document Processing Pipeline

End-to-end document ingestion logic. Depends on `domain`, `persistence`, `pdf-extract`, `fastembed`, `arrow-array`, `arrow-schema`, `tokio`.

- `Cargo.toml`: Dependencies for PDF extraction (`pdf-extract 0.12`), embeddings (`fastembed 6.0.2` backed by ONNX Runtime), and the matching Arrow `58.4` API family.
- `src/lib.rs`: Re-exports `Chunk`. Public functions:
  - `init_embedder(cache_dir)`: Creates the `TextEmbedding` model (`EmbeddingGemma300M` via ONNX backend) in a given cache directory. Blocking call — must be run in `spawn_blocking`.
  - `process_document(pdf_path, document_id, chunk_size, chunk_overlap, embedder, repo, vector_db)`: Full pipeline orchestration — extracts pages, chunks text using a character window estimated at four characters per token (default 512 estimated tokens / 80 estimated-token overlap) with a `"passage: "` prefix, marks status `embedding`, generates embeddings in `spawn_blocking` (via `Arc<Mutex<TextEmbedding>>`), builds Arrow `RecordBatch` with `FixedSizeList<Float32>(768)`, upserts to LanceDB via `merge_insert` (idempotent on `[document_id, page, chunk_index]`), marks status `indexed`. Enforces write-order discipline (LanceDB first, SQLite second).
  - `embed_query(embedder, query)`: Runs query embedding via `fastembed` with `"query: "` prefix. Returns a single `Vec<f32>` (768-dim).
  - `build_rag_prompt(query, search_results)`: Assembles the LLM prompt with document excerpts and page citations.
- `src/extractor.rs`: PDF text extraction using `pdf-extract`'s page-aware API. Keeps physical 1-indexed page positions before filtering blank pages, returning `Vec<(i32, String)>` for citation-grounded chunking.
- `src/chunker.rs`: Character-level sliding-window chunker. Estimates one token as four characters rather than producing exact tokenizer boundaries, caps effective overlap at half the window to preserve progress, and prefixes chunks with `"passage: "` for instruction-aware embedding models. Exports `Chunk { page, chunk_index, content }`.
