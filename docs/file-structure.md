# File Structure

This document outlines the current layout of the application.

## Root Directory

- `package.json`: NPM workspace / scripts for driving both Svelte and Tauri builds.
- `opencode.jsonc`: Agent tooling configuration.
- `docs/`: Architecture, specification documentation, and implementation tracker.
- `frontend/`: The SvelteKit UI.
- `src-tauri/`: The Tauri Rust application shell.

## `frontend/` (SvelteKit UI)

The frontend is a SvelteKit application adapted to run inside a Tauri WebView as a Single Page Application (SPA).

- `svelte.config.js`: Configured for `adapter-static` with SPA fallback (`index.html`).
- `vite.config.ts`: Configured with `strictPort: true` and Tauri-specific dev server ignores.
- `src/routes/`: Client-side rendered pages. Currently contains the entry point (`+page.svelte`) with a simple Tauri IPC `ping` test.
- `src/lib/`: Svelte library files and assets.

## `src-tauri/` (Tauri App Shell)

The Tauri adapter layer connecting the OS, the UI, and the Rust backend.

- `tauri.conf.json`: Core configuration, permissions, and build instructions. Includes the `assetProtocol` configuration scoped to `$APPLOCALDATA`.
- `capabilities/`: JSON files defining exact capabilities mapped to specific window labels.
  - `default.json`: Grants the main window essential baseline permissions.
- `Cargo.toml`: Defines the Rust workspace, including the root Tauri app and the library crates in `crates/`. Depends on `domain`, `persistence`, `sqlx`, and `tokio`.
- `.sqlx/`: Offline query cache generated by `cargo sqlx prepare`. Must be checked into version control so the CI and other developers can build without a live database.

### `src-tauri/src/`

The binary crate — entry point and thin command wrappers.

- `main.rs`: Barebones entry point calling `mrk_ragtag_app::run()`.
- `lib.rs`: Core setup logic. Currently registers a basic `ping` Tauri command, initializes required plugins (`tauri_plugin_fs`, `tauri_plugin_shell`), and re-exports `AppState`.
- `state.rs`: Defines `AppState` — the Tauri managed state holding `SqlitePool`, a job queue `Sender<String>`, and an ephemeral `llm_token` (under `tokio::sync::Mutex` for `.await` safety).

### `src-tauri/crates/` (Business Logic Workspace)

Pure Rust library crates for portable, fast-testing business logic.

#### `crates/domain/` — Shared Types & Errors

Contains zero-infrastructure data types: models, errors, and IPC events. No `sqlx` or `tokio` dependencies.

- `Cargo.toml`: Minimal deps — `serde`, `uuid`, `jiff`, `thiserror`.
- `src/lib.rs`: Re-exports all public types.
- `src/models.rs`: `Document` struct (fields: id, filename, file_type, file_size_bytes, file_hash, storage_path, status, chunk_count, embedding_model, embedding_attempts, timestamps, error tracking) and `DocumentStatus` enum (`Queued | Embedding | Indexed | Failed`).
- `src/error.rs`: `AppError` enum with variants `NotFound`, `Database`, `Io`, `VectorDb`, `QueueFull`, `Internal`. Includes manual `Serialize` impl for Tauri IPC (structured `{ kind, message }`). `From<std::io::Error>` impl for `?` convenience.
- `src/events.rs`: `TokenEvent` enum (`Token | Done | Error`) and `Citation` struct — both derive `Serialize` + `Deserialize` for Tauri event streaming channels.

#### `crates/persistence/` — Data Layer

Database and vector store operations. Depends on `domain`, `sqlx`, `lancedb`, `arrow-*`, `tokio`.

- `Cargo.toml`: Dependencies for SQLite (`sqlx 0.8.6`), LanceDB (`=0.26.2`), and Arrow (`57.2`).
- `src/lib.rs`: Re-exports `DocumentRepository`, `VectorDb`, and `init_pool`. Contains a private `fn sql_err(e: sqlx::Error) -> AppError` helper to work around orphan rule restrictions on `From` impls.
- `src/sqlite.rs`:
  - `init_pool()`: Creates the app data directory, opens a SQLite connection with `SqliteConnectOptions`, runs migrations, returns a `SqlitePool` (max 5 connections).
  - `DocumentRepository`: CRUD operations — `insert`, `update_status`, `get_by_id` (maps raw rows through `DocumentRow → into_domain()`), and `reset_embedding_to_queued` (recovery: flips `embedding` back to `queued` on crash restart). Date/time columns use `CAST(... as TEXT)` with sqlx type overrides since SQLite has no native datetime type.
- `src/lancedb.rs`:
  - `VectorDb`: Holds a LanceDB `Connection` and an `AtomicBool` for FTS index guard.
  - `init()`: Connects to a LanceDB directory on disk.
  - `schema()`: Arrow schema with `FixedSizeList(Float32, 768)` vectors, plus `document_id`, `page`, `chunk_index`, `content` columns.
  - `get_or_create_table()`: Opens existing `chunks` table or creates a new empty one. FTS index is deferred to first write.
  - `upsert_chunks()`: Acquires a static `Semaphore(1)` write lock (prevents LanceDB commit conflicts), runs `merge_insert` on composite key `[document_id, page, chunk_index]` for idempotent upserts, then rebuilds the FTS index on the first call per session (`AtomicBool` swap).
- `migrations/`:
  - `20240101000000_initial.sql`: Creates `documents` table (id, file metadata, processing status, embedding metadata, timestamps, error tracking) with indexes on `status`, `file_hash` (unique), and `created_at`. Creates `app_settings` key-value table.
